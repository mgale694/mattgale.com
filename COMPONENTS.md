# Component compendium

This is the internal design system for Matthew Gale’s portfolio. Update this file whenever a reusable component, prop contract, interaction or shared styling rule changes.

All source paths below are relative to `website/apps/web/src/`. Public assets live in `website/apps/web/public/`.

## Design rules

- **Flow:** hero → about/CV → work → contact. Keep the site one coherent scroll.
- **Palette:** ink `#11110f`, paper `#f3eee7`, signal red `#f0443a`. Accessible red text uses a darker shade on paper and a lighter shade on ink.
- **Type:** Barlow Condensed Black for compressed display headings, Archivo for body copy, IBM Plex Mono for labels. Fonts and licences are self-hosted under `public/fonts/`.
- **Shape:** thin rules and sharp corners. Use rows and spacing for hierarchy.
- **Layout:** one outer frame; `--gutter` controls section insets. Shared breakpoints at 374, 767, 1023 and 1279px; the mobile menu starts below 768px.
- **Appearance:** `tone-ink` and `tone-paper` provide section-local surface, text, muted, border, visual and focus tokens. Default editorial mode alternates tones as in the supplied reference. Light appearance maps ink sections to paper.
- **Motion:** vertical scrolling drives hero depth, masked heading lines, a staged horizontal Work exhibition and the reading rail. Individual name letters occasionally roll in one of four directions. Native scroll/view timelines have a static fallback. Ambient curves, letters and demo media pause off-screen, in hidden tabs, on reduced motion and via the hero pause control.
- **Semantics:** one h1; labelled section landmarks; native anchors, buttons and details/summary controls. Decorative graphics are hidden from assistive technology.
- **Maintenance:** prefer adding typed content over inventing a new component variant. Keep reusable contracts small and domain-specific.

## Shared hooks, data and routing

- `hooks/use-active-section.ts` exports `useActiveSection()` → `{ id, tone }`. It observes a narrow upper viewport band, watches for lazily mounted sections and disconnects on route change. Used only by Header; there is no per-scroll React rerender.
- `content/site.ts` supplies identity, central email, social links, blog settings, navigation, skills, certifications and experience. Keep it browser/Node compatible because the build reads it too.
- `researchUrl(slug?)` in `content/site.ts` joins the configurable external research base and optional slug. Empty base returns undefined, allowing links to disappear cleanly.
- `content/projects.ts` defines `Project`: ID, title, description, details, technologies, status, featured flag, optional live/source/article destinations and `preview`. `ProjectPreview` is a typed image/GIF/video union with source, alt text and dimensions; moving media also requires a still poster. Do not create empty-href controls.
- `lib/utils.ts` retains `cn(...classes)` for clsx + Tailwind class merging.
- `lib/sitemap-generator.ts` runs only during the build, includes local blog URLs only when enabled, and excludes hash anchors/external research from the sitemap.
- Legacy `/about` and `/showcase` routes redirect to their page anchors. Both local blog routes use the shared flag before loading content.
- The optional blog’s route-local `BlogPostCard` and `CodeBlock` are not exported reusable components. They remain part of the preserved blog feature.

## Adding content or components

1. Add project/career content to its typed data file.
2. Reuse the existing section, heading, row, icon and link contracts.
3. Use the local section’s tokens so both appearances work.
4. For a new section, add a stable ID, labelled heading, navigation entry if appropriate, and sensible mobile flow.
5. Document every reusable addition here, including its reduced-motion and keyboard behaviour.
6. Do not add a library or abstraction for behaviour that a native element or a small existing component already handles.

No tests were added or run for this refactor. Validation uses compilation and manual browser review.
